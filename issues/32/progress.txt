## Codebase Patterns
- O pacote real fica em `packages/issue-flow/` (monorepo sem package.json na raiz). Rode `npm run typecheck`, `npm test` e `npm run lint` **de dentro** de `packages/issue-flow/`.
- Testes são colocados ao lado do código (`foo.ts` + `foo.test.ts`), vitest com `globals: true`, include `src/**/*.test.ts`.
- Para mockar módulos, o padrão do repo é `vi.mock('./x.js', ...)` seguido de `const { y } = await import('./x.js')` no topo (top-level await), e `vi.mocked(y)`.
- Loaders/config seguem o padrão de **options injetáveis**: `{ env?: NodeJS.ProcessEnv, warn?: (msg: string) => void, projectRoot?: string }` com defaults (`process.env`, `printWarning`). Ver `LoadWebConfigOptions` em `src/config.ts:188`.
- Imports internos sempre com extensão `.js` (ESM) e protocolo `node:` obrigatório para builtins (regra biome `useNodejsImportProtocol`).
- Biome: aspas simples, trailing commas, 2 espaços, lineWidth 100. Rode `npm run lint` antes de commitar. Se falhar só por formatação, `npx biome check --write <arquivos>` resolve.
- Identificadores que viram segmento de path **sempre** passam por validação antes do `join` (rejeitar vazio, `/`, `\`, `.` e `..`) — ver `normalizeId` em `issues/providers/local.ts:29` e `normalizeIssueNumber` em `storage/paths.ts`.
- Já existe `packages/issue-flow/src/storage/CLAUDE.md` com as regras do módulo de storage; atualize-o quando descobrir algo reusável ali.
- **zod 4**: `.partial()` NÃO remove `.default()` — `z.object({p: z.number().default(1)}).partial().parse({})` devolve `{p: 1}`. Para reusar um campo sem o default use `.unwrap()` (`webConfigSchema.shape.port.unwrap()`), que preserva as constraints. Consequência: camadas intermediárias de precedência nunca podem ser montadas com `.partial()` de um schema com defaults.
- Leitores de arquivo de config **nunca lançam**: ausência é silenciosa (caso comum), qualquer outra falha (JSON inválido, raiz não-objeto, IO) devolve camada vazia + `warn()`. Distinga ausência de erro de IO por `(err as NodeJS.ErrnoException).code !== 'ENOENT'`.
- Precedência oficial do projeto: **CLI > env > `.issue-flow.json` > `config.json` (global) > defaults**, implementada por `mergeConfigLayers()` em `src/config.ts` (shallow, ignora `undefined`).
- Helpers de git que podem falhar legitimamente (sem remote, base branch desconhecida) retornam `null`/default em vez de lançar; só `getProjectRoot`/`getCurrentBranch` lançam. Toda chamada a git passa por `run()` de `utils/shell.ts` (execa com `reject: false`, nunca lança por exit code).
